📌 What is Random Forest?

Understanding the algorithm

Random Forest is an ensemble learning method that builds multiple decision trees during training and merges their predictions. Each tree is trained on a random subset of the data and features — this randomness reduces overfitting and improves generalization.

The final prediction is determined by majority voting across all trees for classification tasks. The more trees, the more stable and accurate the model becomes.

In this project, we trained a Random Forest with 40 estimators in the fixed candidate model. A separate Random Forest grid search was then conducted using training-only cross-validation; its tuned model is reported separately on the Results page.

Final Prediction: ŷ = mode { Tree₁(x), Tree₂(x), ..., Treeₙ(x) }

✅ Advantages

  • Reduces overfitting significantly
  • Handles high-dimensional data
  • Robust to outliers & noise
  • Provides feature importance

❌ Limitations

  • Slower than single tree
  • Less interpretable (black box)
  • High memory usage with many trees

Interpretation

Random Forest achieves the highest subscriber F1-score and ROC-AUC among the candidate models. It provides a more balanced precision–recall trade-off than the other candidates at the default threshold.

All metrics above use the positive class (subscription) for precision, recall and F1. The held-out test set contains 9,043 observations, including 1,058 subscribers and 7,985 non-subscribers.

How this model was evaluated

Consistent experimental design across all four classifiers

  • Input features exclude duration, which is only available after the call.
  • Data are split using a stratified 80:20 train/test split (random state 42).
  • Three-fold stratified cross-validation is performed on the training partition only.
  • Imputation and one-hot encoding are fitted inside scikit-learn pipelines within each fold.
  • Class weighting is applied to Logistic Regression, Decision Tree and Random Forest as configured in the experiment script; no synthetic oversampling is used.
  • Reported test metrics use the default 0.50 probability threshold. The test set is not used for model selection.
